# 六人实质工作与集合包

这里是计划责任分配，不是完成声明。a—f暂时代替姓名；系统已有代码、报告和证据为共同AI协助基线。每人须按任务卡完成自己的核查、分析、最小复现或修改，保存实际成果后再认领贡献。分包和提交压缩文件本身不等于独立编写这些代码。

| 成员 | 板块 | 需要亲自交付的核心成果 | 演讲时间 |
|---|---|---|---:|
| [a](roles/a.md) | 执行系统与工具调用 | 本人绘制的流程及函数定位 | 75秒 |
| [b](roles/b.md) | 工具知识变化与选择性修补 | 真实接口变化对照 | 90秒 |
| [c](roles/c.md) | 实验设计、运行与复现核验 | 任务、策略、版本、分母及来源 | 90秒 |
| [d](roles/d.md) | 指标计算、恢复保持与成本分析 | 本人重算过程、来源和差异处理 | 105秒 |

| [f](roles/f.md) | 报告整合、交付与材料一致性 | 本人逐页检查和真实更正记录 | 60秒 |

六人内容合计9分钟，预留1分钟衔接；另有5分钟问答。a/b/c偏编程，d/e/f可以按现有命令和证据学习并完成分析，但f也要实际核查、更正和组织材料，不能只压缩转交。

## 如何领取和完成

1. 打开自己的任务卡，理解知识点、具体步骤和检查标准。
2. 使用完整共同仓库及已保存证据完成任务。个人ZIP的`source/`只收录该成员负责的文件，不能当作独立可运行项目。
3. 把本人实际完成的输出、发现和修改记录下来；没有修改代码时，可以如实提交独立复核、计算或案例分析，而不是虚构作者身份。
4. 与组员交叉核对接口，提交本人真实工作记录。需要改代码时使用本人分支/提交，保留共同基线与原始实验，不能改分数或冒用别人的账号。

[六个集合包下载](https://github.com/lingenxin3-sketch/pe6203-tool-harness-adaptation/releases/tag/member-work-packages-20261029)。六包按同一完整实验分支提交生成；每包附源提交、负责文件清单、SHA和任务卡。模型与完整运行原件不重复装进六包，仍从共同仓库的三轮Release领取。

## 文件归属与共享

[ownership.json](ownership.json)完整列出实验分支所有跟踪文件的唯一计划负责人。main是该分支的交付子集，所以清单中部分实验凭据只在实验分支存在。每包的source/文件互不重叠；包根目录的说明和任务卡属于共同上下文，不是重复认领代码。不同板块相互依赖，六个包共同构成一个项目。

分工按实质责任划分，不按文件数平均。a负责执行，b负责知识更新，c负责实验，d负责数字，e负责事实案例，f负责最终一致性。所有人仍应知道系统总目标、三种策略、486/324的区别和65.1%/5.6%的含义。

包中的实际贡献模板保持待填写。只有本人完成并留下可核查记录后，才能更新为实际贡献；本次自动准备不替成员完成独立复核。
