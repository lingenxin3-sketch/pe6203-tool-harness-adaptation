# 追加实验冻结与故障协议

2026-10-29，适用于本实验分支。完整执行指南见同目录文件。

## 来源与可比性

原轮为 `runs/final-v1`，第一新增轮为 `runs/repeat-r2-20261029`，第二新增轮为 `runs/final-r3`。后者在启动前从未执行的原计划名 repeat-r3-20261029 改为与原轮等长的8字符目录，以恢复原资源可见性。每轮配置仍为 repeats=1，分别实际执行 162 条。原轮 manifest、执行记录、失败收据和评分均不改写。合并只建立带轮次、原文件路径和 SHA-256 的分析视图，不修改旧 repeat 编号或 manifest。

原配置、18 个任务、三个策略、三个版本、工具清单、工具源码、基础模型、推理参数、最大步数和评分协议必须一致。actor/updater 为原 Qwen3 4B，temperature=0，seed=6203，最大 12 步。actor 上下文 16384。judge 为原 Qwen2.5 7B，使用原容量修订 24576、原 rubric 和 judge-only adapter。依赖摘要和旧记录核查在 `artifacts/repeats-20261029/preflight.json`。新轮实际 manifest、模型服务和评分收据还需再次核对。配置或源码不符则分开报告，不强行合并，也不增加第三个新轮。

固定 seed 和 temperature 的重复主要反映同配置下的执行稳定性。输出目录本身会改变提示词里的路径，工具生成编号、缓存和硬件状态也可能产生差异。耗时只作描述，不把硬件变化归因于更新方法。没有显著性或普遍胜出的预设结论。

运行中补充的输入核验发现：Windows 长路径会使部分 PDF 文件名在新输出目录下不再出现在 AI 的资源清单中，即使实际文件字节完全一致。原轮与新增轮必须额外逐条核对清单；存在该差异时判为不能严格合并，分别报告。不能用“任务可能不使用这些 PDF”代替输入一致性证据，也不声称清单差异已被证明导致分数变化。已运行记录保留，不为修正目录名称重新执行，不额外增加第三个新轮。

第一新增轮中，策略名称长度也造成部分资源清单差异，因此该轮策略差异含输入可见性的混杂，不能全部归因于更新方法。第二新增轮启动前，已用不调用模型的27组文件系统检查验证等长目录：覆盖一、二、三位任务号、三种策略和三个版本，资源文件名可见性均与原轮对应记录一致。测试目录已单独清理，未改源文件或正式记录。配置和模型设置不变；第二新增轮仍需核对实际提示词。即使第二新增轮单独与原轮可比，仍不把存在差异的第一新增轮塞入486条合并结论。

## 编排和恢复边界

新增脚本只负责外层编排、状态、续跑和发布，不修改 `tool_adapt` 冻结核心。首次运行调用原执行函数。显式恢复时，受检查的 AST 适配器只替换输出目录存在检查，并在每个 episode 边界读取已保存结果、恢复对应知识、跳过该条执行。没有模型或方法指令变更。原、新脚本哈希和测试保留。

输入清单差异在执行阶段发现后，管理程序需采用强化后的合并门。`repeat_supervise_existing.py` 在保留原执行进程句柄并先接上防睡眠后，只替换旧管理进程。它等待同一 actor 进程自然结束，再显式恢复修正后的管理程序。已完成 actor 记录全部跳过，不重发模型请求。接管收据、进程 ID 和测试保留，任何接管异常都停在真实状态，不清空数据重跑。

已保存记录绝不自动重跑。工作目录已存在但 result.json 未完整提交时，停止恢复并保留现场，等待人工处理，不能清空重试。正常运行中的模型和工具错误保留为真实失败。原失败轨迹恢复程序只组装已有事件供评分，同时保留原 failure-record.json 和事件哈希；无可用或不一致轨迹则停止，报告未完成。

评分使用原 `judge_with_capacity.py`。已有效评分记录直接跳过；只处理 awaiting_judge。judge_failed 不静默重评；连接中断导致未落盘时，保留 agent-record 及中断日志，明确确认原进程已终止后再决定是否恢复未评分记录。官方评分器本来允许无效 JSON 的有限格式重试，这个统一协议保持不变。不得修改原分数、挑选最好结果或删除失败。

正式前发布状态页并从 GitHub 读回。运行中计划每 15 分钟发布快照，发布者只读原子落盘的 result.json。所有时间为新加坡 UTC+8。进程使用 Windows SetThreadExecutionState 防止闲置睡眠，只在进程存活期间生效，不更改系统电源计划，不能保证合盖、断电、重启或网络中断时持续运行。

每轮必须完成执行、失败证据整理、评分、162 条唯一矩阵检查、协议审计、独立统计核对。第一轮新增还必须完成结果提交、独立新 Release 证据包、匿名下载 SHA-256 核验及最终状态提交的远端读回，才允许第二轮。任一门槛失败则发布受阻状态并停止第二轮。不会覆盖 v1.0.0，不强推、不合并 main、不替团队提交课程。

## 文本与原始字节的哈希

Git可能把Windows文本的CRLF换行规范化为LF。因此分支文件的远端逐文件核验，以对应commit中的Git blob字节为准；原始证据ZIP保留本地文件字节，包内PACKAGE_MANIFEST.json列出这些原始字节的逐文件SHA-256，附件.sha256核对整个ZIP。不能把分支文本下载的哈希和ZIP原始文件的哈希混为同一对象。

已实际核对r2-actor-start-runtime.json：本地原始字节哈希以9b0d42开头，commit文本哈希以d6b245开头，差异仅为CRLF转LF。运行收据中的原始字节哈希须在证据ZIP中核验，远端发布回执中的文件哈希则对应Git blob；两种核验均保留，不为让哈希相等而改写旧证据。
