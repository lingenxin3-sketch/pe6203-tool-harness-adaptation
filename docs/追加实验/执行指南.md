2. 用不调用模型的测试检查：每轮 162 个唯一 `(strategy, version, task_id)`；三轮可比时 486 个唯一 `(round, strategy, version, task_id)`；缺失、重复、失败和未评分能被识别；旧/新来源不丢失，不能覆盖原结果；中断恢复不会静默重跑已完成的记录。任何合并视图须保留各自 manifest 与原始哈希，不能仅改 `repeats` 后改写旧记录。
3. 如有必要，使用最小开发任务验证本地模型、MCP 工具、保存、评分和统计的实际链路；开发任务不计入正式结果。使用现有本地模型，不使用付费 API，不请求、显示或上传凭据。先确认程序和机器能否在锁屏/无人值守时继续；无法保证就明确说明，不承诺一夜完成。
4. 在正式运行前预先写明故障恢复和重试边界。每条执行产生真实记录；保留模型错误、工具异常和基础设施失败，区分失败类型，不为挑选好结果重跑。对中断评分只处理明确未评分记录，保留前次执行证据。
5. 第一轮新增：执行→评分→核对 162 条和失败状态→生成清晰结果与局限→按第四节推送并从远端验证。**只有第一轮结果和必要证据已安全上传并验证，才开始第二轮新增。**若发布失败，推送阻塞说明（如可行），暂停第二轮，不强推或声称已上传。可在同一实验分支进行分阶段提交，不覆盖第一轮产物。
6. 第二轮新增：使用同一冻结协议另存独立目录，执行、评分、验证 162 条，然后发布第二轮结果。如果旧轮与两次新增轮全部可比，再生成 486 条、三次的组合分析；如不兼容，分开展示并说明原因。
